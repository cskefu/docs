# 标签和属性

在 春松客服 中，**标签 (Labels)** 和 **自定义属性 (Custom Attributes)** 是实现客户细分、自动化流程和数据分析的核心工具。如果把春松客服比作一个图书馆，标签就是贴在书上的“分类色卡”，而属性就是书扉页上的“详细索引”。

---

## 1. 标签 (Labels) —— 快速分类与工作流驱动

标签主要用于对**对话 (Conversations)** 或 **联系人 (Contacts)** 进行视觉上的快速分类。

### 核心用法：

* **手动标记：** 客服在聊天时，可以在右侧边栏一键点击添加。例如：`紧急`、`Bug反馈`、`意向客户`。
* **视觉区分：** 标签带有颜色，能让客服在混乱的收件箱列表中一眼看到哪些是重点。
* **侧边栏筛选：** 点击左侧导航栏的标签名，可以瞬间筛选出所有带有该标签的对话。

### 进阶场景：

* **自动化：** 你可以设置“自动化规则”。例如：如果客户的消息包含“退款”，系统自动打上 `投诉` 标签并转交给主管。
* **报表分析：** 在“报告”面板中，你可以按标签统计。例如：本月有多少个对话被标记为 `产品咨询`。

---

## 2. 自定义属性 (Custom Attributes) —— 深度画像与数据同步

属性用于记录**结构化数据**。它能让 春松客服 变成一个懂业务的 CRM。

### 属性的两个层级：

1. **联系人属性 (Contact Attributes)：** 记录客户固有的信息。
* *示例：* 会员等级、所属行业、注册时间、公司规模。


2. **对话属性 (Conversation Attributes)：** 记录单次咨询的信息。
* *示例：* 订单编号、产品型号、问题严重程度、本次通话意向。



### 支持的数据类型：

* **文本 (Text)：** 自由录入。
* **数字 (Number)：** 如消费金额。
* **列表 (Link/Dropdown)：** 预设选项（推荐，方便后续筛选）。
* **布尔值 (Checkbox)：** 如“是否已续费”。

---

## 3. 标签与属性的区别

| 特性 | 标签 (Labels) | 自定义属性 (Attributes) |
| --- | --- | --- |
| **主要形态** | 彩色色块 | 键值对 (Key-Value) |
| **主要用途** | 流程状态、快速分类 | 客户详细资料、业务参数 |
| **灵活性** | 高，可随时增删 | 规范，需先在设置中定义 |
| **自动同步** | 较难从外部系统同步 | 非常适合通过 API/SDK 从后台同步 |

---

## 4. 最佳实践：如何组合使用？

为了达到最高效率，建议按以下逻辑配置：

### 第一步：定义属性（在系统设置中）

先去 `设置 -> 自定义属性`，把你的业务指标填进去。

### 第二步：SDK 自动赋值

在你的网站代码中，通过 春松客服 SDK 将用户的会员级别传给属性：

```javascript
window.cskefu.setCustomAttributes({
  plan: 'Enterprise',
  last_order_id: '88888'
});

```

### 第三步：基于属性打标签

设置自动化规则：

* **条件：** 当 `plan` 等于 `Enterprise`。
* **动作：** 自动打上标签 `VIP`，并指派给“资深客户经理”。

---

## 5. 管理技巧

* **保持简洁：** 标签不要超过 20 个，否则客服在选择时会陷入“选择困难症”。
* **规范命名：** 建议使用 `动作-目标` 的形式，如 `待处理-发票`、`已解决-退款`。
* **权限控制：** 只有管理员可以创建新标签和属性，防止普通坐席乱建标签导致数据混乱。
